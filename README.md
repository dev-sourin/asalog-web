# あさログ（Web版）

毎朝の朝ごはんの写真・内容と、寝た時刻・起きた時刻を記録して、仲間と見せ合うWebアプリです。
メールアドレスで会員登録ができ、承認制・参加停止・データの書き出し／削除まで入っています。

- 画面：HTML / CSS / JavaScript だけ（ビルド不要）。スマホのホーム画面に追加するとアプリのように使えます
- 裏側：Supabase（会員登録・データベース・写真の保存）
- 置き場所：Netlify / Vercel / GitHub Pages / Cloudflare Pages など、静的サイトを置ける所ならどこでも

---

## ファイル構成

```
asalog-web/
├─ index.html            画面
├─ styles.css            見た目
├─ app.js                動き
├─ config.js             ← Supabase の URL とキーをここに書く
├─ manifest.webmanifest  ホーム画面に追加したときの設定
├─ icon.svg / icon-192.png / icon-512.png
└─ supabase/schema.sql   データベースとアクセス制御の設定（Supabaseで1回実行）
```

## セットアップ（30分ほど・パソコン推奨）

### 1. Supabase のプロジェクトを作る

1. https://supabase.com でアカウントを作り、「New project」を押す
2. Region は **Northeast Asia (Tokyo)** を選ぶ
3. データベースのパスワードを決めて作成（このパスワードはアプリでは使いません。控えておくだけでOK）

### 2. データベースを設定する

1. 左メニューの **SQL Editor** を開く
2. `supabase/schema.sql` の中身を全部貼り付けて **Run**
3. 「Success」と出れば完了。テーブル（profiles / posts / likes / app_config）と写真の保存場所（photos）ができます

あとで schema.sql を直したときも、同じように全部貼って Run すれば上書きされます。

### 3. config.js にキーを書く

1. Supabase の **Project Settings → API**（または「API Keys」）を開く
2. **Project URL** と **anon public key**（新しい画面では **publishable key**）をコピー
3. `config.js` に貼る

```js
export const SUPABASE_URL = "https://xxxxxxxx.supabase.co";
export const SUPABASE_ANON_KEY = "eyJhbGciOi...";
```

> anon / publishable key はブラウザに置いてよい公開用のキーです。データは schema.sql のアクセス制御（RLS）で守られています。
> **service_role key（secret key）は絶対に config.js に書かないでください。**

### 4. サイトを公開する

いちばん簡単なのは Netlify Drop です。

1. https://app.netlify.com/drop を開く
2. `asalog-web` フォルダをまるごとドラッグ＆ドロップ
3. `https://○○○.netlify.app` のようなURLが発行される（サイト名はあとで変更可）

GitHub Pages や Vercel でも、フォルダをそのまま置くだけで動きます（ビルド設定は不要）。

> `index.html` をダブルクリックして開く（file://）だけでは動きません。
> 手元で試すときは、フォルダ内で `python3 -m http.server 8000` を実行し、http://localhost:8000 を開いてください。

### 5. ログインの戻り先URLを登録する

Supabase の **Authentication → URL Configuration** で：

- **Site URL**：公開したURL（例：`https://asalog.netlify.app`）
- **Redirect URLs**：同じURLを追加（手元で試すなら `http://localhost:8000` も）

これを忘れると、確認メールやパスワード再設定メールのリンクが正しく戻ってきません。

### 6. 最初に自分が登録する（＝管理者になる）

**いちばん最初に参加登録した人が自動で管理者になります。** 公開したらすぐ、自分で新規登録 → メール確認 → 参加登録まで済ませてください。
その後「管理」タブで、必要なら「承認制」に切り替えます。

## 使い方

| 画面 | できること |
|---|---|
| みんなの朝 | 参加中のメンバーの公開投稿を日付順に表示。「おはよう」で反応 |
| 記録する | 写真、食べたもの、作った人、中身、そろい方、寝た／起きた／朝食の時刻、目覚め、場所・だれと・満足度・気分、ひとこと。公開範囲（みんな／自分だけ）と「写真は載せない」を選べる |
| わたしの記録 | 連続記録、平均睡眠・起床、14日間の睡眠バー、作った人の割合、アルバム。プロフィール編集、書き出し（JSON/CSV）、Claude版データの取り込み、パスワード変更、退会 |
| 管理（管理者のみ） | 参加者の承認・停止・解除、管理者の追加、メンバーの公開投稿の一括削除、承認制の切り替え、グループ名・メッセージ、全データの書き出し |

### 人を招待する

公開したURLを送るだけです。相手はメールアドレスで新規登録 → 参加登録をします。
承認制にしている場合は、管理画面で「承認する」を押すと使えるようになります。

## アクセス制御（schema.sql で守っていること）

画面の表示ではなく、データベース自体で制御しています（Row Level Security）。

- 承認待ち・停止中の人は、ほかの人の投稿もプロフィールも読めず、投稿もできない
- 「自分だけ」の記録は本人しか読めない（管理者も読めない）
- 「写真は載せない」にした写真は、本人以外は取り出せない（写真の保存場所も非公開で、表示は期限付きURL）
- 状態（参加中／承認待ち／停止）と権限（管理者）は管理者しか変えられない。参加登録時に自分を管理者にすることもできない
- 投稿の作者はサーバー側で本人に固定され、他人になりすまして投稿・編集できない
- 停止したメンバーの投稿は、ほかの人のタイムラインから自動で消える
- 退会すると、アカウント・記録・おはよう・写真がすべて削除される

## メールを日本語にする（おすすめ）

Supabase の確認メールは最初は英語です。**Authentication → Emails（Email Templates）** で変更できます。

**Confirm signup（登録確認）**
- 件名：`あさログ｜メールアドレスの確認`
- 本文：
```html
<p>あさログへの登録ありがとうございます。</p>
<p>下のリンクを開くと登録が完了します。</p>
<p><a href="{{ .ConfirmationURL }}">メールアドレスを確認する</a></p>
```

**Reset password（パスワード再設定）**
- 件名：`あさログ｜パスワードの再設定`
- 本文：
```html
<p>下のリンクから新しいパスワードを設定してください。</p>
<p><a href="{{ .ConfirmationURL }}">パスワードを再設定する</a></p>
```

> Supabase 標準のメール送信は、送れる数がかなり少なく制限されています（お試し用）。
> 人数が増えてきたら **Authentication → Emails → SMTP Settings** で、Resend などのメール送信サービスを設定してください。

## Claude版あさログからの引っ越し

1. Claude版の「わたしの記録 → アカウントとデータ」で **データを書き出す（JSON）**
2. Web版でログインし、「わたしの記録 → Claude版あさログのデータを取り込む」でそのファイルを選ぶ

- 記録（時刻・内容・タグなど）と公開範囲が引き継がれます
- 写真は引き継がれません（必要なら、記録を編集して写真を付け直してください）
- 同じ日付の記録がすでにある日は取り込みません
- 各メンバーが自分の分を取り込む形です（「自分だけ」の記録は本人しか書き出せないため）

## 費用と運用の目安

- Supabase 無料プランで、仲間内〜数百人規模なら十分に動きます
- **無料プランは、1週間ほどアクセスがないとプロジェクトが一時停止します。** 管理画面から再開できます。毎日使われていれば止まりません
- 写真は端末側で長辺1280pxに縮めてから保存するので、1枚およそ150〜300KBです
- 本格運用に入るときは、Supabase Pro（月25ドル〜）にするとバックアップや一時停止の心配がなくなります
- 公開前に、利用規約とプライバシーポリシー（睡眠や食事の記録を扱うため）を用意しておくと安心です

## よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| 「初期設定が必要です」と出る | config.js に URL とキーが入っていない |
| 確認メールのリンクを開くとエラー | 手順5の Site URL / Redirect URLs が未設定 |
| 登録後、承認待ちのまま | 承認制になっている。管理者が「管理」タブで承認する |
| 写真が表示されない | schema.sql を最後まで実行できていない（photos の設定が入っていない）。もう一度 Run する |
| 管理タブが出ない | 自分より先に誰かが登録して管理者になった。Supabase の Table Editor で profiles の自分の行の role を `admin`、status を `active` にする |
